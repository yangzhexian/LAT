# 第二轮：分段调度、遥测与长文渲染

适用版本为 `0.2.1-beta.6`。本轮沿用第一轮的任务归属、可取消传输、会话鉴权及模型生命周期，在不降低默认翻译质量设置的前提下减少排队、进程创建、数据传输与界面排版开销。真实模型吞吐量和交互延迟需要在相同设备及文本上验收，本文件不把机制改进换算为未经测量的提速百分比。

## 单模型与有界任务队列

`TranslationScheduler` 同时只授予一个推理执行权。长文在当前分段生成、校验并提交断点之后让出执行权；不会打断尚未校验的半个分段。划词请求因此需要等当前分段结束，并受公平调度限制，不承诺立即开始。重复段落缓存与纯格式段仍保留原有处理路径。

默认容纳一个执行任务和八个等待任务。每次排队最多等待 120 秒，超时返回 `translation_queue_timeout`；已完成分段保留。`max_pending_translations` 和 `queue_wait_timeout_seconds` 可配置，达到容量返回 `translation_busy`，不会清除已有断点。队列等待时的 `waiting` 事件包含 `job_id`、`request_source`、`queue_position` 和可显示的消息。

划词具有较高优先级；存在普通任务等待时，最多连续授予三个划词分段。等待满五秒的任务按先后顺序获得更高优先级，避免持续划词使长文无法继续。每次分段完成重新排队，等待时限重新计算；总文档可以超过单次等待时限。

`request_source` 是桌面发送的 `workspace` 或 `selection`，仅管理凭证有权选择。普通第三方 API 请求始终归类为 `api`，无论是否伪造内部字段。来源不影响恢复断点的指纹，凭证归属、源文本、语言、模型及推理选项仍影响指纹。

任务注册之后即可取消，等待中的任务也有独立取消事件。重复恢复仍在执行或排队的同一任务会被拒绝；恢复已结束请求会分配新事件，避免清除旧 HTTP 连接的断连信号。正在运行或等待的断点不参与 TTL/LRU 清理；结束后最多保留八个非活动断点，断点仅存于本次网关进程内存。模型管理拒绝与全部已准入任务冲突，退出会取消执行及等待任务。

## GPU 采集与增量读取

`GpuTelemetry` 从网关启动持续采集，默认保留最近五分钟数据。NVML provider 使用 Python 标准库 `ctypes`，从 NVIDIA 驱动的系统目录加载 DLL，一次初始化并复用设备句柄；按 UUID 区分显卡，显存转换为 MiB，功率转换为 W。温度、功率或利用率单项不支持时保留 `null`，不填零，也不因为一个指标缺失就放弃其他可用指标。接口与单位依据 [NVIDIA 设备查询文档](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlDeviceQueries.html)，生命周期依据 [NVML 初始化与清理文档](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlInitializationAndCleanup.html)。

NVML 初始化失败或运行中失去驱动连接时回退到隐藏的 `nvidia-smi` 子进程。回退成功时最短两秒采集一次，失败时最短五秒重试，单次子进程超时为两秒。重复读取回退缓存保留原始采样时间戳，不伪造高频样本；前端采用配置周期与 `provider_interval` 中较大的值。单次监测生命周期不反复重试已失效的 NVML，重启监测器后才重新尝试。

| 接口 | 内容与缓存策略 |
| --- | --- |
| `GET /admin/telemetry/gpu` | GPU 最新状态及保留历史；带 `since`、`session_id` 时只传时间戳严格大于游标的样本 |
| `GET /admin/telemetry/inference` | 当前推理、最近调用与累计用量；不附带 GPU 历史或 GGUF 元数据 |
| `GET /admin/architecture` | `{architecture: ...}` 静态架构，支持 ETag / If-None-Match，未变化时 304 无响应体 |
| `GET /admin/telemetry` | 保留旧版组合响应，供既有客户端兼容使用 |

GPU 快照含 `session_id`、`cursor`、`reset`。游标非有限值或负数会被拒绝；会话不同或游标在最新样本之后时返回完整保留历史并指示重置。前端按时间戳去重，保留五分钟、最多 601 点，再派生用户选择的趋势范围；切换范围不重新下载历史。

模型页只轮询当前的 GPU 或推理选项卡，切换或页面隐藏时取消旧请求；架构页独立以不短于五秒的周期发条件请求。旧会话或已取消的迟到响应不能覆盖缓存。架构缓存依据模型文件的路径、大小、修改时间和模型标识失效，并保存已序列化响应；304 不重复深拷贝张量列表或序列化整个对象。

## 可复现的运行时配置

固定的 llama.cpp `b10545` 使用 `--parallel 1` 保证单个槽位使用完整上下文，显式传入批次、微批次、Flash Attention、KV 缓存类型与 prompt cache 设置，开启性能计时供已有看板读取。参数定义核对了 [b10545 官方服务端文档](https://github.com/ggml-org/llama.cpp/blob/b10545/tools/server/README.md)。

| 配置 | 默认值 | 范围与用途 |
| --- | --- | --- |
| `batch_size` | `2048` | 32–8192，输入逻辑批次 |
| `ubatch_size` | `512` | 16–2048，且不超过 batch，物理微批次 |
| `flash_attention` | `auto` | `auto` / `on` / `off` |
| `kv_cache_type` | `f16` | `f16` / `q8_0`，默认不量化 KV |
| `cache_prompt` | `true` | 在服务端及每次请求中显式设置，复用相同输入前缀 |

设置通过本地 JSON 或 README 对应的环境变量修改，需重启网关及模型。`/admin/status` 的 `inference_config` 返回实际配置。可选 `q8_0` 要求 Flash Attention 为 `auto` 或 `on`，配置阶段直接拒绝与 `off` 的组合，依据是 [b10545 的 V 缓存校验](https://github.com/ggml-org/llama.cpp/blob/b10545/src/llama-context.cpp#L3293-L3300)；其兼容性、显存与质量仍需在设备上验证，建议保持默认配置作为比较基线。本轮不改变采样温度、模型量化、格式保护、输出校验或重试策略，也不通过并行加载多个模型换取吞吐量。

## 长文界面更新

主窗口将连续 `progress` 事件按 100 ms 合并，已校验分段、排队、计划和终态立即更新。每次提交有独立请求身份，取消或断连时刷新已有进度并清理定时器，终态后的迟到事件不能写入当前任务。文本面板 memo 化，回调与 Unicode 字符计数缓存，归一化只在提交时执行。

LaTeX 只在翻译页可见且选择预览时挂载。预览限制为最多 4,000 个 UTF-16 字符及 40 个完整公式；不会截断代理对，发现未闭合公式就在其之前停止。有界前缀相同则不重复调用 MathJax。界面明确提示范围，并引导切回“文本”查看和复制全文；完整原文、译文及历史均不裁剪。这是有界前缀预览，尚未实现全文分页排版。

自动化测试以 100,000 个 Unicode 字符输入、128,000 字符输出和 1,000 次进度事件检查数据完整性及排版调用生命周期，使用 jsdom / MathJax fixture。它们不等同于真实 WebView2 的帧率、内存或真实模型吞吐量基准。
